# Current Supabase integration status

The live application database contains the 22-table application model plus `mobile_profile_backups`. Mobile now supports email/password Auth and personal cloud backup/restore through an authenticated, revision-checked RPC. Configured APKs expose Account & Backup on the entry page, menu and profile tab.

Configured mobile builds require sign-in before learning. The current profile is linked and backed up automatically after sign-in; profiles created or opened afterward also link automatically. Changes are backed up while the app is running with a connection; failed saves retain local data and retry. Linked profiles are restricted to their account on the device, including pending offline uploads. Signing out closes the active profile and removes open navigation routes. Restore creates a separate device profile, preserving unsent work. Local history/XP is unverified personal data; backups never write `xp_ledger` or verified completions.

The server now exposes `learning-api`: canonical profile/session/draft mutations, server-evaluated attempts, atomic completion/XP, paginated change sync, progress reports, admin content/account APIs and private image delivery. The baseline catalog is published (11 topics / 53 activities / 30 active evaluators). See `docs/LEARNING_SERVER_API.md` for routes, payloads, authorization, deployment and validation boundaries.

Mobile 1.3.1+5 now sends canonical profiles, sessions, drafts, attempts and completions through a durable per-profile journal in the same local snapshot as progress. Immutable request IDs and frozen in-flight draft payloads survive retry/restart; account switches stop stale acknowledgements. The UI distinguishes local learning XP from cached server-confirmed XP. Restoring a backup forks mutable session/draft/attempt IDs and preserves answers. Profile revision conflicts offer an explicit choice of device/cloud metadata. Personal backup remains available; incremental change-feed merging is not enabled in mobile. The admin dashboard UI and live AI/compiler provider infrastructure remain separate work. See `docs/PHONE_READINESS.md` for the installable APK and validation scope. Builds without Supabase dart defines retain offline mode.

Mobile supports in-app email-code confirmation and resend with cooldown. The REA-aligned `supabase/templates/confirmation.html`, confirmation subject and Matlingo sender name were applied and verified through the authenticated Management API on 2026-10-26. SMTP credentials, confirmation requirements and the 8-digit OTP length were preserved. Actual mailbox delivery remains a phone/user check.

Business revision conflicts now return SQLSTATE PT409 through public RPCs, avoiding PostgREST's repeated retries of custom 40001 errors. `learning-api` v4 maps these to HTTP 409 with a safe reason. Canonical and backup conflict responses were verified through real HTTP, in addition to SQL rollback tests.

See supabase/README.md. Historical reports are retained only in local development notes and must not be presented as current validation.
